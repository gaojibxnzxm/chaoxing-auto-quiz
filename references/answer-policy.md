# 答题策略与隐私红线

本文件是「如何决定答案、如何保护隐私、何时提交」的唯一权威来源。SKILL.md 只写摘要，具体规则以本文件为准。

## 1. 提交策略

- **默认直接提交**。答完一章即调用 `btnBlueSubmit()`，再在主文档确认弹窗点「提交」，随后读取「最终成绩 XX 分」。
- **暂存是例外**：仅当用户明确说「先保存」「暂时保存」「暂存」时，才调用 `noSubmit()`（`btnSave` 按钮）。暂存不会消除「待完成」状态，也不能产生成绩。
- **提交不可撤销**。首次在一个新课程上使用时，提交前向用户提示一次；同一课程后续章节按默认直提，不再逐次确认。
- **提交后以事实为准**：iframe 内文本可能仍缓存显示「待完成」，不要据此判定失败。以目录树上的绿色完成标记 + 页面「最终成绩」为准。必要时用 `shot` 截图目视确认。

## 2. 答案置信度与查证流程

目标：不要高错误率。宁可多问一次，不要硬猜。

### 2.1 题干混淆的成因

学习通部分题库对题干做**字形混淆**：把关键词替换成形近生僻字（例：把常用词换成读音/字形相近的冷僻字）。`innerText` 拿到的是替换后的字，直接 WebSearch 往往搜不到。

### 2.2 还原与查证步骤

1. **读结构，不只读文字**：先按 `dom-and-js.md` 识别题型和选项列表，从题干里**未被混淆的字**反推被替换的关键词。
2. **结合领域知识还原**：消防类课程用消防设施/消防法规常识还原（如「引燃蚊帐」类描述对应「用火不慎」）。其他课程用对应专业常识。
3. **WebSearch 查权威依据**：只搜还原后的**知识点/概念**，例如「湿式报警阀 工作原理」「海因里希法则 内容」。优先权威来源（国家标准、教材、政府/监管机构网站）。**禁止**把学校名、用户名、课程名等任何个人标识拼进搜索词。
4. **交叉验证**：当两个来源冲突时，以教材/国标/官方为准；仍冲突的题进入「不确定清单」。

### 2.3 置信度阈值与提问规则

分三档处理：

| 档位 | 判定 | 动作 |
|---|---|---|
| 高 | 题干清晰，或还原后能查到明确权威依据 | 直接作答 |
| 中 | 大致有方向但有一处关键表述拿不准 | 继续查证；查到依据升为高，查不到降为低 |
| 低 | 题干还原不出来、搜索无果、两个依据冲突、纯记忆模糊 | 加入「不确定清单」，**不作答或跳过该题** |

**集中提问**：把本章所有「低」档题一次性列给用户（题号 + 题干还原猜测 + 候选选项 + 已查到的依据），一轮问完，不要一题一问打断用户。用户回复后再批量补答。

**禁止行为**：
- 禁止为提高完成率对低置信度题随机选 A/B/C/D。
- 禁止把「不确定」伪装成「已确认」提交。
- 禁止在未查证的情况下凭第一直觉锁定答案。

## 3. 隐私红线（硬性）

以下规则任何情况下不得突破：

1. **不落盘身份信息**：禁止把学校名、用户名、学号、真实课程名写入本 skill 的任何文件、临时产物、工作记忆或对话外的笔记。
2. **不落盘课程 token**：URL 中的 `chapterId`、`courseId`、`clazzid`、`cpi`、`enc`、`openc` 等参数**只允许在 shell 变量和 bsk 会话内存中存在**，禁止重定向到文件、禁止写入日志、禁止写入记忆。references 中只写参数名，不写任何真实值。
3. **查询脱敏**：WebSearch 查询串只含题目知识点，不得含个人/机构标识。
4. **截图即删**：`shot` 截图写入系统临时目录，查看完当场删除；收尾时核对临时目录无遗留截图。
5. **不写工作记忆**：本任务不向 `.workbuddy/memory/` 写入任何答题记录，避免留存可回溯信息。
6. **会话收尾**：结束前 `bsk session stop`，不留活跃会话。

## 4. 合规边界

- 仅用于用户**自己的账号、自己的课程**。
- 不绕过验证码、不破解、不批量注册、不用于他人账号。
- 自动化可能违反平台或学校规定，使用者自行判断并承担相应责任。
